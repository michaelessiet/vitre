# Vitre ↔ Electron feature-parity matrix

Status of the native Rust/GPUI app (`crates/vitre-*`) against the Electron desktop app
(`apps/web` + `apps/desktop`), per the migration plan's parity-QA process. Updated from a
189-row sweep of the Electron codebase on **2026-09-03** (after the add-project flow landed
in `24f497a63`).

**Snapshot (recounted 2026-09-14): 104 present · 52 partial · 34 absent · 1 waived.**
Phase 1/2 native cleanup and phase 3/4 macOS verification are summarized below.
These historical counts permitted documented native UX differences; they are not
an acceptance claim against the user's September 15 requirement for 1:1 features
and design, except explicitly requested glass/animation/native enhancements.
They do not imply Linux/Windows verification.
Phase 0 — git diff gutter, the vim subset and M2 polish — is complete.
Subsequent implementation and remaining parity gaps are recorded in the roadmap below.
M1 (chat core) and M2 slices 1–5
(files, tree ops, LSP bridge, ⌘S/format, QuickSearch + command palette, sidebar grouping,
add-project) are the "present" mass; the "absent" mass is dominated by whole subsystems the
master plan schedules as M3+ (preview, settings,
knowledge graph, multi-environment). M3 slices 2.1 (right-panel dock), 2.2/2.3 (diff
engine + diff panel), 2.4 (turn-diff changed-files cards) and 2.5 core (terminal drawer:
grid renderer, lifecycle, input arbitration, tabs/groups, theme) landed 2026-09-03; 2.6
source control (git actions, branch toolbar, thread delete + worktree cleanup), 2.7
diff review comments, 2.8a terminal contexts (grid selection → add-to-chat →
composer chips → timeline chips) and 2.8b project scripts (header actions control)
landed 2026-09-04.

How to update: flip a row's status in the same PR that changes it; add a `Done <date> (<sha>)`
note. Rows that will never be ported get status `waived` with a written reason (e.g. WSL
sources before a Windows build).

QA note: sandboxed verification runs can't inject clicks, so thread-scoped behaviors are
driven by `VITRE_OPEN_THREAD=<thread-id>` (selects the thread once the shell carries it)
plus seeded `~/.vitre/*.json` state files, then screenshots.

## September 15 native language-support follow-up

TSX/JSX now use complete host + JSX highlighting with correct capture precedence,
embedded-template highlighting and module-extension aliases. Previously empty
Swift/C#/CMake/Protobuf query configurations are populated. Native completions
honor Unicode identifiers and server filtering/sorting metadata; document sync
is ordered, custom-language cold attachment is retried, and stale auto-import,
definition and formatting responses are guarded. JSX comment toggling preserves
valid markup. Shift+F12 opens a virtualized references list; Cmd+Shift+Space
and argument typing show independent caret-anchored parameter hints. Ctrl+Space
and editor context-menu actions expose the language tools.

The native `languages` fixture validates these React language-service paths
against the real bundled TypeScript service. The follow-up adds semantic-token
styling, before/after rename and text-edit quick-fix previews, linked snippets,
simultaneous selections, and local stdio DAP debugging with live LLDB evidence.
See [`vitre-editor-tools.md`](vitre-editor-tools.md) for supported workflows,
shortcuts, tests and limits. Resource/command-based refactors, advanced snippet
and multi-cursor compatibility, full debugger/test integration, external-library
navigation, universal grammars and unrestricted large-file editing remain;
this does **not** assert full Zed/VS Code parity.

## September 15 settings and context-menu correction

Settings acceptance is **reopened**, not complete. The route now has compact
provider rows, real provider switches, expandable configuration, native status
and artwork, bounded centered content, left-aligned navigation, top-right search,
and Knowledge Graph controls. General's complete control inventory, provider
wizard/environment/model-management parity, search navigation, Connections, and
the remaining LSP/source-control/archive workflows still require acceptance work.

Both sidebar variants now share thread overflow and secondary-click actions:
inline rename, mark unread, copy path/ID, branch carry-over, lifecycle actions and
guarded deletion. Archive rows expose Unarchive/Delete; assistant/plan Markdown
exposes selection/source copying. Nested context menus, macOS Control-click,
native text-input menu ownership and disabled-item keyboard navigation have
focused mouse-dispatch regression coverage. The isolated native `menus` pass
exercises both sidebars, rename save/cancel, copy target identity, selection
preservation, project menus, provider expansion and provider form save/removal.
See `docs/vitre-handover.md` for evidence and the explicit remaining gaps.
